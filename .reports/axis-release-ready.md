## Release-day checklist (for the authorized run)

1. Owner authorizes: set `RELEASE_CHANGESSETS='true'`, approve
   the `npm-publish` environment, dispatch `Release`.
2. `changesets/action` opens the version PR (`0.1.0` +
   generated changelog) or publishes directly when there is
   nothing to version beyond pending changesets.
3. After the Axis publish: Kern swaps its vendored `file:` spec
   to the semver range under separate release authorization
   (Kern-side checklist, not this repo).
4. Never publish from a laptop (`npm publish` by hand bypasses
   every gate above); never set the HOLD var back without
   recording why.
